# AI 能力画像模型 v1.0

平台把“能力评测”与“能力画像”分成两层：

1. **证据层**：沿用设计方案的 Verify / Spec / Code / Collab 四个评分维度，以及 V1–V4、S1–S4、C1–C4、P1–P4 共 16 个可追溯评分点。每个分数必须来自评测结果中的 criterion、测试、度量、抽取或人工证据。
2. **画像层**：把证据按能力目录聚合为 8 个员工可理解的 AI 能力域。能力域不是第二套评分规则；它只对已经存在的评分点做归一化加权聚合。

## 八个能力域

| 能力域 | 关注问题 | 当前关联证据 |
|---|---|---|
| AI 认知与选型 | 是否理解 AI 边界并选对模型、工具和协作方式 | P1、P2 |
| 任务理解与拆解 | 能否把目标、约束、假设和变化点拆成可验收任务 | S1、S2、S4 |
| 提示词与上下文工程 | 能否组织角色、上下文、约束、示例和自检 | P1、P3 |
| 检索与事实核验 | 是否主动检索并验证引用、假设和边界事实 | V3、S3 |
| 工具与 Agent 编排 | 能否把 AI 与代码、测试、检索和自动化组合成工作流 | P2、P4 |
| 输出评审与测试 | 是否用测试、边界、回归和证据审查 AI 产出 | V1、V2、V3、V4 |
| 工程交付与自动化 | 能否把产出沉淀为可维护、可测试、可发布的交付物 | C1、C2、C3、C4 |
| 安全、合规与风险 | 是否识别数据、权限、隐私、版权和运行风险 | S3、V2、C2 |

## 计算口径

- 单个评分点的百分比为 `score / max × 100`。
- 单个能力域按该场次已出现评分点的 `score` 与 `max` 加总后归一化；多场记录再取历史平均。
- 无任何关联评分点时，`percent` 为 `null`，状态为“待评测”，不使用默认分、不用相邻能力推断。
- 有分数时，状态按历史平均百分比标记：`≥85` 为“优势”、`60–84.99` 为“稳定”、`<60` 为“待提升”；这些状态用于画像引导，不改变原始评测等级。
- `evidenceMode=derived` 表示当前能力域由 V/S/C/P 关联证据聚合；后续接入 Claude 的 Spec/Collab 抽取或专门能力评测后，可在新目录版本中增加 `direct` 证据，不改变历史目录版本。
- 部门中位数按同一组织路径下其他员工的历史平均能力域分数计算；只有可见且已揭晓的结果才进入比较。
- 能力目录版本随 API 返回，已发布版本不可原地修改；调整能力域、映射或阈值必须新增目录版本。

员工 API：`GET /api/v1/profiles/{subjectId}/capabilities`。

管理员 API：`GET /api/v1/admin/capabilities`。不带参数返回全员画像；使用 `orgPath` 选择部门（包含子团队），再用逗号分隔的 `subjectIds` 选择部分人员。部门或选定人员的群体画像使用 `includeProfiles=false`，返回的是选择范围内按有效证据计算的平均能力（含四维、8 域和 16 个评分点）及每项有效样本数，不铺开个人卡片；`includeProfiles=true` 才返回个人明细。管理员允许查看尚未对员工揭晓的内部成绩。
