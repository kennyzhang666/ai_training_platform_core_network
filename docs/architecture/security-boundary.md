# 安全边界（本地适配器）

生产 `TRUSTED_GATEWAY` 接入请先阅读：[统一认证网关接入手册](../deployment/trusted-gateway-sso.md)。

本地开发默认使用 `X-Employee-Id` 作为认证适配器输入，服务端从文件适配器读取角色、状态和组织路径。生产接入内部 SSO 时，`OIDC` 模式由 API 验证网关转发的 JWT，`TRUSTED_GATEWAY` 模式由 API 验证统一认证网关生成的 HMAC 身份头；两种模式都会根据工号、姓名和部门幂等登记员工并同步组织归属。`POST /api/v1/auth/sso` 仅用于本地适配器和测试，生产请求身份以 Guard 校验后的认证上下文为准。请求体中的 `actorId` 只为兼容旧客户端保留，所有管理操作都会忽略它并使用认证上下文中的操作者。

员工账号不能通过管理接口创建。管理员只能为 SSO 已登记的员工配置部门归属和角色；部门匹配失败时员工保留空组织路径，只能由全局管理员完成首次归属。全局管理员可维护所有组织和管理员角色；部门管理员只能维护授权路径及子路径，不能配置其他管理员，也不能删除其权限范围根部门。部门删除还会拒绝下级部门、员工、权限绑定、训战范围或其他业务引用仍存在的情况。

提交路径有三层边界：

1. `workspacePath` 必须位于 `LOCAL_WORKSPACE_ROOT`，并拒绝 `grader`、`hidden-tests`、`contracts`、`.git`、`node_modules` 和 `tmp`；
2. 上传归档先检查声明大小，再在解包时检查路径穿越、软链接、文件数量和膨胀总量；
3. `LOCAL_GIT_ROOT` 只允许相对仓库路径，Git 通过 `rev-parse` 锁定 commit 后由 `git archive` 生成只读归档。

评测执行是独立边界：Worker 只领取平台已经冻结的批次，解包时再次验证路径、软链接、文件数、体积和快照哈希；Code Agent 通过 `shell: false` 启动，运行配置可受可执行文件白名单约束。平台 API 只接收契约化结果，不信任 Agent 自报的员工身份和总分。

生产环境仍需要在网关层校验 SSO 断言或 OIDC/JWT，清理外部请求自带的 `x-employee-id` 和 `x-trusted-*` 头，并使用明确来源列表和 HTTP 方法配置 CORS；Worker 应使用独立服务身份。实际评测必须运行在禁网、非 root、资源受限、临时文件系统隔离的 K8s Job 或等价沙箱中。本地实现不应被直接暴露到生产网络。
