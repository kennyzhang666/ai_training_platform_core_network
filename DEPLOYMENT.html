以上是保守起步配置，不是目标环境 SLA。自动验收覆盖 100 人名册和 20 人同时身份访问、提交写入；实际 CPU、内存和评测总时长主要由 Code Agent、赛题引擎、模型调用方式和交付件大小决定。

端口与网络

端口/方向用途单服务器规则

02 · 一页纸傻瓜部署

下面是 v1.1.0 Linux 原生发布包的最短路径。Linux 包根目录包含 install.sh。只需填写 PostgreSQL 14、首位管理员和 Worker 身份；公司内网 LDAP 与 codeagent -p 非交互参数已经内置，随机密钥由脚本生成，安装和数据库迁移均不访问外网。Windows 部署步骤保留供上一版包使用。

准备：以管理员身份打开 PowerShell；安装 PostgreSQL 14；准备可运行的 Code Agent；把 ZIP 与同名 .sha256 放到 D:\Release。平台在迁移前读取数据库实际版本，低于 14 将停止安装。
1

创建数据库

在 pgAdmin 查询工具中以 PostgreSQL 管理员执行，先替换密码：

PostgreSQL SQL
CREATE ROLE ai_training LOGIN PASSWORD '<独立数据库强密码>';
CREATE DATABASE ai_training OWNER ai_training ENCODING 'UTF8';
2

校验并解压发布包

管理员 PowerShell
Set-Location D:\Release
$version = '<新发布版本>'
$archive = Resolve-Path ".\ai-training-platform-$version-win32-x64.zip"
$expected = (Get-Content "$archive.sha256").Split()[0].ToLower()
$actual = (Get-FileHash $archive -Algorithm SHA256).Hash.ToLower()
if ($actual -ne $expected) { throw "发布包 SHA-256 校验失败" }
New-Item -ItemType Directory -Force C:\AITraining | Out-Null
Expand-Archive -LiteralPath $archive -DestinationPath C:\AITraining -Force
Set-Location C:\AITraining
3

执行一键安装

PowerShell 或双击
Set-Location C:\AITraining
.\install.cmd

脚本会请求管理员权限、生成独立随机密钥并打开配置文件。填写本页“只改这些配置”中的数据库、管理员和 Worker 身份，保存并关闭记事本后，脚本继续完成预检、数据库迁移、启动和开机自启注册。

4

确认安装结果

管理员 PowerShell
Set-Location C:\AITraining
.\deploy\single-node\manage.cmd Doctor
.\deploy\single-node\manage.cmd Status

install.cmd 失败时按输出修正 deploy\single-node\.env，再次运行同一个入口；脚本不会覆盖已有配置。

5

开放用户访问端口

管理员 PowerShell
New-NetFirewallRule -DisplayName "AI Training Platform 8080" `
  -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
Invoke-WebRequest http://127.0.0.1:8080/ -UseBasicParsing | Select-Object StatusCode

用户访问 http://服务器IP:8080/。首次使用配置中的首位全局管理员工号登录。

准备：使用具有 sudo 权限的部署账号；安装公司内网提供的 PostgreSQL 14；准备 Code Agent；把 tar.gz 与同名 .sha256 放到 /tmp/release。平台在迁移前读取数据库实际版本，PostgreSQL 14 可直接通过兼容检查。
1

创建数据库

Linux shell + psql
sudo -u postgres psql <<'SQL'
CREATE ROLE ai_training LOGIN PASSWORD '<独立数据库强密码>';
CREATE DATABASE ai_training OWNER ai_training ENCODING 'UTF8';
SQL
2

校验并解压发布包

Linux shell
cd /tmp/release
version='<新发布版本>'
sha256sum -c "ai-training-platform-$version-linux-x64.tar.gz.sha256"
sudo mkdir -p /opt/ai-training
sudo tar -xzf "ai-training-platform-$version-linux-x64.tar.gz" -C /opt/ai-training
sudo chown -R "$USER":"$(id -gn)" /opt/ai-training
cd /opt/ai-training
chmod +x install.sh deploy/single-node/manage.sh
3

执行一键安装

Linux shell
cd /opt/ai-training
EDITOR=vi ./install.sh

脚本生成独立随机密钥并打开配置文件。填写数据库、管理员和 Worker 身份并退出编辑器后，脚本完成预检、数据库迁移、启动和 systemd 开机自启；安装系统服务时会按需请求 sudo。

4

确认安装结果

Linux shell
cd /opt/ai-training
./deploy/single-node/manage.sh Doctor
./deploy/single-node/manage.sh Status
systemctl status ai-training-platform.service --no-pager
5

开放用户访问端口

按服务器发行版选择一条，不要两条都执行：

RHEL / openEuler / CentOS
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
curl -I http://127.0.0.1:8080/
Ubuntu / Debian 使用 UFW 时
sudo ufw allow 8080/tcp
curl -I http://127.0.0.1:8080/

用户访问 http://服务器IP:8080/。

03 · 只改这些配置

离线包已经提供正确的平台路径和运行时配置。首次部署只修改下表，不要删除模板中的其他字段。

配置项填写内容约束
DATABASE_URL刚创建的 PostgreSQL 14 用户、密码和数据库单服务器主机固定 127.0.0.1；特殊字符需 URL 编码
TRUSTED_GATEWAY_HMAC_SECRET安装器自动生成不要手工复制或对外发送
LDAP_GATEWAY_SESSION_SECRET安装器自动生成的另一条独立密钥不会与 HMAC 密钥复用
PLATFORM_BOOTSTRAP_GLOBAL_ADMIN_EMPLOYEE_NO首位全局管理员工号仅空系统第一次有效
EVALUATION_WORKER_EMPLOYEE_NO已有全局管理员工号用于 Worker 领取和回传批次
EVALUATION_WORKER_NAME该工号在 SSO 中的真实姓名必须与首次登记身份一致
EVALUATION_WORKER_TRUSTED_GATEWAY_SECRET安装器自动同步为网关 HMAC 密钥不能使用浏览器 Cookie
CODE_AGENT_COMMANDCode Agent 可执行文件或绝对路径公司内网默认 codeagent，通常无需修改
CODE_AGENT_ARGS_JSON参数 JSON 数组默认 ["-p","{{prompt}}"]；-p 使用非交互模式，Prompt 由平台按赛题自动组合
CODE_AGENT_ALLOWED_EXECUTABLES允许启动的可执行文件，逗号分隔必须包含命令名或绝对路径
EVALUATION_ARCHIVE_MAX_FILES单个引擎包或交付 ZIP 文件项上限默认 10000
EVALUATION_ARCHIVE_MAX_UNCOMPRESSED_BYTES单个 ZIP 解压后总量上限默认 536870912（512 MiB）
EVALUATION_ARCHIVE_MAX_FILE_BYTESZIP 内单文件上限默认 134217728（128 MiB）

公司内网 LDAP 默认值

以下参数来自已验证的公司内网登录代码，发布包已直接写入，无需在安装时修改。平台按工号绑定 China\工号，并优先从 title 的“工号,姓名,部门”格式解析姓名和部门，部门缺失时回退到 department。

发布包内置配置
LDAP_SERVER=china.huawei.com
LDAP_PORT=389
LDAP_USE_SSL=false
LDAP_START_TLS=false
LDAP_BASE_DN=dc=china,dc=huawei,dc=com
LDAP_BIND_PREFIX=China\
LDAP_ACCOUNT_ATTRIBUTE=sAMAccountName
LDAP_TITLE_ATTRIBUTE=title
LDAP_DEPARTMENT_ATTRIBUTE=department
LDAP_NAME_ATTRIBUTE=displayName

仅在 LDAP 环境变化时覆盖

如果公司目录以后切换为 StartTLS、LDAPS、其他域或其他属性名，再修改上述默认值。使用企业私有 CA 时在 .env 中增加 LDAP_CA_CERT_FILE 的绝对路径。

StartTLS

.env 片段
LDAP_PORT=389
LDAP_USE_SSL=false
LDAP_START_TLS=true
LDAP_CA_CERT_FILE=<企业CA证书路径>

LDAPS

.env 片段
LDAP_PORT=636
LDAP_USE_SSL=true
LDAP_START_TLS=false
LDAP_CA_CERT_FILE=<企业CA证书路径>

Code Agent 运行配置

公司内网默认

.env
CODE_AGENT_COMMAND=codeagent
CODE_AGENT_ARGS_JSON=["-p","{{prompt}}"]
CODE_AGENT_ALLOWED_EXECUTABLES=codeagent

模型由公司环境内置。{{prompt}} 由 Worker 自动组合赛题、instruction、Skills、提交清单和结果契约。

调用公司自有 bridge

.env
CODE_AGENT_COMMAND=company-evaluation-bridge
CODE_AGENT_ARGS_JSON=["--manifest","{{manifestPath}}"]
CODE_AGENT_ALLOWED_EXECUTABLES=company-evaluation-bridge

如果命令不在系统 PATH 中，三个字段都填写绝对路径。Windows npm 产生的 .cmd 入口会尝试解析到原生可执行文件；普通批处理和 PowerShell 脚本不会通过 shell 执行。

04 · 推荐单服务器部署

办公网浏览器 | v Nginx :8080 ── auth_request ──> LDAP3 网关 127.0.0.1:8081 ──> 企业 LDAP | +── Web 静态文件 `── Platform API 127.0.0.1:3000 ──> PostgreSQL 127.0.0.1:5432 | +──> data/artifacts + data/engine-packages `──> 独立 Worker ──> Code Agent ──> 赛题评测引擎

目录边界

目录内容备份
data/交付件、引擎包、Worker 引擎缓存、pip 缓存必须与数据库一致备份
runtime-state/PID、临时上传、批次工作区、日志、渲染后 Nginx 配置可重建；故障排查时保留
backups/一致性数据库快照与 data 归档复制到独立磁盘或备份系统
deploy/single-node/.env密码、密钥、LDAP 和运行配置不进入平台备份；单独加密保管
release-manifest.json包内逐文件 SHA-256、平台和版本随版本包保存

为什么正式环境不用 JSON 或 SQLite

少于 100 人的长期数据和约 20 人同时提交仍会产生并发写入、租约、幂等回传、审计和历史结果。正式兼容基线为 PostgreSQL 14；它提供平台所需的事务、唯一约束和可恢复备份，现有迁移不使用 15/16 专属语法。文件仓储只用于本地开发。简化部署通过“同机 PostgreSQL”减少组件，而不是退回不可靠的数据存储。

换端口

只在冲突时修改，并保持同一份配置：

.env 示例
HOST=127.0.0.1
PORT=3100
PLATFORM_API=http://127.0.0.1:3100/api/v1
LDAP_GATEWAY_HOST=127.0.0.1
LDAP_GATEWAY_PORT=8181
SINGLE_NODE_LISTEN_PORT=8282

Doctor 会检查端口范围、重复、占用、回环监听以及 Worker API 地址是否一致，并把配置写入 Nginx。

05 · 标准分离部署

使用条件：只有在数据库、对象存储或 Worker 必须由不同团队维护时才使用。原生离线包管理脚本固定校验 single-node，不能拿它假装一键启动标准模式。标准模式需要平台开发/运维人员按组件部署并完成目标环境 UAT。
用户 | v 企业 HTTPS / SSO 网关 |-- / -> Web 静态资源 `-- /api/ -> Platform API（先保持单实例） |-- 独立 PostgreSQL |-- S3-compatible 对象存储 `-- Evaluation Batch API ^ | 独立 Worker 节点 -> Code Agent / 隔离执行环境

标准生产最小环境变量

Platform API
NODE_ENV=production
PLATFORM_DEPLOYMENT_PROFILE=standard
HOST=127.0.0.1
PORT=3000
PLATFORM_REPOSITORY=postgres
DATABASE_URL=postgresql://<用户>:<URL编码密码>@<数据库主机>:5432/<数据库>?schema=public

OBJECT_STORAGE_MODE=s3
OBJECT_STORAGE_BUCKET=ai-training-platform
OBJECT_STORAGE_REGION=us-east-1
OBJECT_STORAGE_ENDPOINT=https://<对象存储地址>
OBJECT_STORAGE_ACCESS_KEY_ID=<访问键>
OBJECT_STORAGE_SECRET_ACCESS_KEY=<密钥>
OBJECT_STORAGE_FORCE_PATH_STYLE=true
OBJECT_STORAGE_PREFIX=platform

PLATFORM_IDENTITY_MODE=TRUSTED_GATEWAY
TRUSTED_GATEWAY_HMAC_SECRET=<至少32字符随机密钥>
TRUSTED_GATEWAY_MAX_AGE_SECONDS=90
SSO_IDENTITY_SYNC_INTERVAL_SECONDS=300
EMBEDDED_EVALUATION_WORKER=false
CORS_ORIGINS=https://<平台域名>
独立 Worker

EVALUATION_WORKER_EMPLOYEE_NO=<服务身份对应管理员工号>
EVALUATION_WORKER_NAME=<SSO真实姓名>
EVALUATION_WORKER_DEPARTMENT=<SSO部门>
EVALUATION_WORKER_TRUSTED_GATEWAY_SECRET=<与API一致的HMAC密钥>
EVALUATION_BATCH_ROOT=/var/lib/ai-training/evaluation-batches

ENGINE_CACHE_ROOT=/var/lib/ai-training/worker-engines

CODE_AGENT_COMMAND=codeagent

CODE_AGENT_ALLOWED_EXECUTABLES=codeagent

标准部署顺序

  1. DBA 创建 PostgreSQL 数据库、用户、备份和来源 ACL；
  2. 存储团队创建私有 bucket、访问键、生命周期和来源 ACL；
  3. 身份团队配置 OIDC 或可信网关，API 端口只允许网关访问；
  4. 发布机生成 Web/API 产物和目标平台依赖，目标机不联网构建；
  5. 使用正式 DATABASE_URL 执行 prisma migrate deploy；
  6. 启动一个 API 实例并验证健康检查、数据库和 S3 上传；
  7. 启动独立 Worker，验证服务身份、命令允许列表和批次领取；
  8. 完成 SSO、ZIP/Git 提交、在线评测、线下导入、备份恢复和权限验收；
  9. 只有在领域 Repository 拆分、容量和冲突测试通过后，才增加 API 实例。

数据库独立、交付件仍在应用机

该折中模式仍使用 PLATFORM_DEPLOYMENT_PROFILE=single-node 和 OBJECT_STORAGE_MODE=local，只把 DATABASE_URL 指向独立 PostgreSQL。它减少数据库运维责任，但本地交付件仍决定应用服务器不能水平扩容，备份必须同时包含远端数据库快照和本地 data/。

06 · 认证、LDAP 与 HTTPS

模式选择

模式适用场景平台接收推荐度
内置 LDAP3 网关公司提供 LDAP/AD，缺少现成 Web SSO 网关HMAC 签名身份头单服务器推荐
企业可信网关已有统一登录与反向代理HMAC 签名身份头标准部署推荐
OIDC已有 HTTPS Issuer、Audience 和 JWKSBearer JWT可用
LOCAL开发机X-Employee-Id生产禁止

可信网关身份头

网关在验证 SSO 会话后生成以下五个头，并在转发前删除浏览器自带的同名头：

请求头内容
X-Trusted-Employee-No工号
X-Trusted-Name真实姓名
X-Trusted-Department部门名称、ID 或组织路径
X-Trusted-Issued-AtUTC ISO-8601 时间
X-Trusted-Identity-SignatureHMAC-SHA256 小写十六进制
签名原文
employeeNo\nissuedAt\nname\ndepartment

OIDC 配置

Platform API
NODE_ENV=production
PLATFORM_IDENTITY_MODE=OIDC
OIDC_ISSUER=https://idp.example.internal/
OIDC_AUDIENCE=ai-training-platform
OIDC_JWKS_URL=https://idp.example.internal/.well-known/jwks.json
OIDC_EMPLOYEE_CLAIM=employeeNo
OIDC_NAME_CLAIM=name
OIDC_DEPARTMENT_CLAIM=department

生产 Issuer 和 JWKS 必须使用 HTTPS。当前支持的算法以实现和身份测试为准，新增算法必须增加真实密钥对测试。

HTTP 与 HTTPS

隔离内网 HTTP

当前单服务器离线包的最短路径。设置：

.env
INTRANET_HTTP_ONLY=true
LDAP_GATEWAY_COOKIE_SECURE=false
SINGLE_NODE_LISTEN_PORT=8080

LDAP 到目录服务器仍必须使用 StartTLS 或 LDAPS。

企业 HTTPS

由企业入口网关或外部 Nginx 终止 TLS：

身份网关
INTRANET_HTTP_ONLY=false
LDAP_GATEWAY_COOKIE_SECURE=true
CORS_ORIGINS=https://ai-platform.example.internal

当前单服务器管理器尚未自动生成 HTTPS 配置，不能只改 Cookie 开关就声称完成 HTTPS。

不能绕过：API 的 3000 端口和 LDAP 网关的 8081 端口不向用户网段开放；浏览器不能直连 API；LDAP 密码、Cookie、HMAC、OIDC Token 和完整身份断言不能写入日志。

Install 可以重复执行，用于重新体检、迁移、启动并刷新开机自启配置。Uninstall 只移除 Windows 开机任务或 Linux systemd 单元并停止进程，不删除 .env、PostgreSQL 数据、data/ 或 backups/。

备份规则

  • Backup 会短暂停止平台，导出 PostgreSQL 一致性快照并归档 data/，随后恢复原运行状态；
  • 备份不包含 .env，密钥和数据库密码必须单独加密保管；
  • 备份生成后复制到独立磁盘或公司备份系统，不能只留在同一块服务器磁盘；
  • 恢复前先停止服务。恢复失败时脚本会尝试放回原数据目录，并保留失败目录供排查；
  • 不能只恢复数据库或只恢复交付件；两者必须来自同一个备份时间点；
  • 至少每季度在非生产环境做一次真实恢复演练。

08 · 制作与发布离线包

Windows 包必须在 Windows x64 发布机构建；Linux 包必须在与目标服务器发行版和 glibc 基线兼容的 Linux x64 发布机构建。Prisma 引擎、Python 扩展和 Nginx 不能跨平台复制。

GitHub 原生构建 Ubuntu 22.04 x64

推荐：推送正式版本标签后，release-linux-ubuntu-22.04.yml 在 GitHub 的 Ubuntu 22.04 x64 Runner 中执行原生构建；既有标签可在 Actions 页面手动输入标签补建。
  1. 源码只从 vX.Y.Z 不可变标签检出，并核对标签与 package.json 版本；
  2. Node.js、Python 和 Nginx 固定版本并逐项校验 SHA-256；
  3. 在 Linux 原生环境重新安装依赖、生成 Prisma 产物、执行完整测试和发布门禁；
  4. 解包后再次运行 Node、Python、Nginx 冒烟检查；
  5. 把 .tar.gz 和 .tar.gz.sha256 同时上传到对应 GitHub Release。

GitHub 构建使用真实 PostgreSQL 14 执行全部版本化迁移、事务、租约、备份恢复和并发集成测试，并证明发布包可在 Ubuntu 22.04 原生环境组装。它不替代公司内网 Ubuntu 22.04.5 服务器上的 PostgreSQL 14、LDAP、Code Agent、多人提交和断网验收。

09 · 上线验收

按顺序执行，上一项失败时不要跳过。

  1. 发布包 SHA-256 与发布方一致；
  2. Install 成功生成配置、完成全部数据库迁移并注册开机自启；
  3. Doctor 检查运行时、Python 模块、端口、数据库、Nginx 和 Code Agent 通过；
  4. Start 后 Status 显示 API、LDAP 网关、Worker 和 Nginx 正常；
  5. 服务器本机访问 API health 和 LDAP health 成功；
  6. 用户地址未登录时进入登录页；
  7. 真实 SSO/LDAP 登录成功，个人中心工号、姓名和部门正确；
  8. 首位管理员进入管理后台，创建或匹配组织并配置角色；
  9. 普通员工不能访问管理接口；部门管理员不能越权访问兄弟部门；
  10. 管理员创建赛题版本、交付契约和训战时间/对象；
  11. 员工在开放时间提交 ZIP 或受控 Git 分支；目录错误能得到明确诊断；
  12. 管理员精确选择一名或多名员工发起评测；
  13. Worker 下载交付件和引擎，Code Agent 逐份评分并回传；
  14. 平台显示已完成、详细报告、排名、证据链和个人画像；
  15. 重复回传保持幂等，重新评测产生新运行而不覆盖旧结果；
  16. 执行一次 Backup，在非生产环境完成 Restore；
  17. 服务器重启后不执行人工命令，确认平台自动恢复；
  18. 日志中没有密码、Cookie、HMAC、Token、SSO 断言或完整源码。
