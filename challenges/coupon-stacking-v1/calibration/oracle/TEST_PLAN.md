# 超市计价测试设计

测试依据是 SPEC.md、CLARIFICATIONS.md 和 CHANGE.md。所有断言先由规格推导，不将当前实现输出当作正确答案。测试只调用公开接口，除异常类型及 code 外，还检查金额和 applied 的内容与顺序。本文件是作者参考交付的一部分，测试范围与下面的记录对应。

## 等价类与边界

商品分为合法输入与不合法输入，合法输入再区分零价、普通价格、多个数量、会员价缺省、会员价为零与会员价等于原价。非法输入覆盖负价、零数量、浮点值、布尔值和超出原价的会员价。布尔值在 Python 中是整数子类，不能仅凭 isinstance(value, int) 判为合法。券分为满减券与折扣券，进一步覆盖零门槛、最小合法优惠、零封顶、等于优惠额的封顶、较小封顶、非法比例和重复券号。时间覆盖生效前一微秒、生效时刻、截止前一微秒、截止时刻和过期后，另外检查无时区的 now 和券时间。

R1 的错误检查使用 assertRaises 并核对 code，防止把 TypeError 当作业务异常通过。R2 的数量检查至少使用数量二和数量三，避免只测 quantity=1 无法发现漏乘。R3 的截止时刻是独立输入，与“已经过期一天”的普通输入分开。R5 使用 25 分九折、15 分九折以及不恰好落在半分的金额，区分舍入规则和普通运算。R8 逐字段比较完整 Quote，不能只判断对象存在或应付非负。

## 组合策略

组合以不同规则交汇处为主。会员价行与普通行同时存在时，折扣只针对普通行，会员节省额独立累计，再共同参与满减。排除品类同时覆盖完全相同的字符串、仅大小写不同的字符串和普通品类。两张折扣券设置不同到期时间、相同到期但不同优惠、完全相同优惠但不同券号，分别核对选择顺序。再与两张满减券组合，检查只选各一张，以及应用券号的顺序。

为避免错误互相抵消，舍入测试不混入被排除品类，门槛相等测试先不叠加折扣。组合发现失败后，再使用这些独立输入确认原因。完整 E1 覆盖小计、折扣、满减和应付，会员与封顶组合使用 E3，测试其所有字段而不是只有 payable。数据表中同时保存输入与手工计算的期望，不在表的生成阶段调用待测函数录制答案。

## 规格空白

- G1：依据 CLARIFICATIONS.md，满减门槛使用会员价和折扣之后的 J。覆盖原价达标但 J 不达标、会员价后不达标、J 恰好等于门槛三种情况。
- G2：依据 CLARIFICATIONS.md，整体折扣基数只舍入一次。两行各 15 分九折应合计优惠 3 分，再补两行各 25 分和三行各 1 分，确认没有逐行舍入。
- G3：依据 CLARIFICATIONS.md，threshold_off 是实际抵扣。满减面额超过 J 时检查返回的抵扣额等于 J，应付为零；J 为零时不登记券号。

## 变更影响

test_best_percent_coupon_selected 依赖旧版最大优惠优先，修改为最早到期优先，期望选中更早到期但优惠较小的券。test_percent_tie_breaks_by_code 不能在到期时间不同的情况下直接比较券号，应补到期时间优先和到期相同两个场景。test_rounding_half 固化了当前实现输出，改为按四舍五入计算期望值，25 分九折应优惠 2 分。旧测试中合法的主流程、过期忽略、空购物车和数量校验继续保留其验证意图，整理进按条款命名的数据表。

CH2 新增会员价后，补非会员、会员无专价、零会员价、专价等于原价和多数量。会员价与折扣互斥只是行级规则，并不排斥订单再使用满减。每次更改期望值同时检查完整 Quote，避免新字段遗漏而测试仍然通过。

## 不覆盖说明

本题不测试库存、支付、数据库、网络接口、商品录入界面或券发放流程。购物车和券是函数参数，使用纯内存合成数据即可。测试不依赖系统当前时间、不读取文件、不请求外网。随机扩展只能在固定种子下使用，并且有独立的规格计算依据；本次核心断言采用有限数据表，优先保证任何失败都能复现。没有使用私有成员或实现文件内容识别评测版本。
