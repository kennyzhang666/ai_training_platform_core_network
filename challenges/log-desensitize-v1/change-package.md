# 变更包：分级脱敏 `level="strict"`

> 请在完成第一轮实现并通过自测后再打开本文件。

## 变更背景

外部分析团队分两类：内部安全团队需要保留 IP 网段和邮箱域名做聚类分析；第三方审计团队不允许看到任何网络位置和企业域名。因此脱敏需要分级。

## 变更内容

`desensitize` 增加关键字参数 `level`，取值 `"standard"`（默认）或 `"strict"`。

`"strict"` 相对 `"standard"` 只改两条规则：

| 类别 | `standard` | `strict` |
|---|---|---|
| IPv4 | 保留前两段：`10.20.*.*` | 四段全部脱敏：`*.*.*.*` |
| 邮箱 | 域名保留：`z***@corp.example.com` | 域名整体替换为 `***`：`z***@***` |

其余规则（手机号、身份证、银行卡、密钥、姓名）在两个级别下**完全一致**。

## 不变量

1. **可追溯标记不受级别影响**。标记始终取自原始值，因此同一个 IP 在 `standard` 和 `strict` 下得到相同的 `#标记`，只是掩码不同。
2. **默认行为不变**。不传 `level` 时必须与变更前逐字节一致，由回归测试验证。
3. **非法 `level` 抛异常**，与非法 `text` 使用同一异常类型。
4. **幂等仍然成立**，且在每个级别内部成立。

## 你需要补充的交付内容

- `SPEC.md` 的 `## 6. 变更影响分析` 中说明：受影响的规则、受影响的验收用例、以及你如何确认其余规则未被波及；
- `SPEC.md` 的 `## 4. 验收用例` 中补充 `strict` 级别的用例；
- `transcript.md` 中补充 `CHANGE` 和 `REGRESSION` 两个阶段的轮次，`REGRESSION` 轮必须记录你对 `standard` 既有用例的回归结论。

## 评分关联

本变更包直接对应 `V4`（变更回归验证）、`S4`（变更影响定位）和 `P4`（变更定位与验证）。只改代码不更新规格和记录，这三个评分点都会失分。
