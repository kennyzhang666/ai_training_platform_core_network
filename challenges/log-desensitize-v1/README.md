# 运维日志脱敏（log-desensitize-01@1）

> 本题考核的是**规格驱动开发（SDD）**，不是把正则写对。
> 代码只占 20 分；规格质量、验收设计和你与 AI 的协作过程占 40 分，验证占 40 分。
> 先写规格、再写验收用例、再让 AI 实现、最后用你自己的用例验证——这个顺序本身就是被评分的对象。

## 1. 业务背景

运维平台每天产生大量日志。日志需要共享给外部分析团队，因此必须先脱敏，但脱敏后仍要能回答这类问题：

- 「同一个用户」在这段日志里出现了几次？
- 报错集中在「同一个 IP 段」还是分散的？

也就是说：**掩码必须不可逆，但相同原始值必须仍然可关联**。这是本题所有设计取舍的出发点。

## 2. 交付目标

实现 `src/desensitize.py` 中的：

```python
def desensitize(text: str, *, level: str = "standard") -> str
```

返回脱敏后的文本，**行数、行顺序和所有非敏感字符必须原样保留**。

`level` 参数见第 6 节变更包。第一轮实现只需支持 `"standard"`。

## 3. 脱敏规则

对每一类敏感信息，先按下表生成掩码，再按第 4 节追加可追溯标记。

| 类别 | 识别方式 | 掩码结果 |
|---|---|---|
| 手机号 | `1[3-9]` 开头的 11 位数字 | 保留前 3 位和后 4 位，中间 4 位为 `****`：`138****8000` |
| 身份证 | 18 位，第 7–14 位是合法出生日期（`19xx`/`20xx` + 合法月日），末位为数字或 `X`/`x` | 保留前 6 位和后 4 位，中间 8 位为 `********`：`110101********1234` |
| 银行卡 | 16–19 位数字 | 只保留后 4 位，其余每位一个 `*`：`************7890` |
| 邮箱 | 常规邮箱格式 | 本地部分保留首字符、其余固定替换为 `***`，域名保留：`z***@corp.example.com` |
| IPv4 | 点分十进制，每段 0–255 | 保留前两段，后两段各替换为一个 `*`：`10.20.*.*` |
| 密钥 | `token` `secret` `password` `passwd` `pwd` `apikey` `api_key` `access_key`（大小写不敏感）后接 `=` 或 `:` 的值 | 值整体替换为 `***` |
| 中文姓名 | `name=` `username=` `user_name=` `realname=` 或 `姓名：` `用户：` `申请人：` `操作人：` 之后的 2–4 个汉字 | 保留第一个汉字，其余每字一个 `*`：`张*`、`欧***` |

## 4. 可追溯标记

每个被脱敏的值，在掩码后追加 `#` 和一个标记：

```text
标记 = sha256(原始值的 UTF-8 字节).hexdigest()[:6]
```

例如 `13800138000` → `138****8000#a6942f`。

标记的取值是**原始值本身**，不含前缀、分隔符或引号。密钥规则中，标记取自被替换掉的值（`token=abc` 的标记取自 `abc`）。姓名规则中，标记取自那 2–4 个汉字。

这样：同一原始值在任何位置都得到同一标记，不同原始值几乎不可能碰撞，而掩码本身不可逆。

## 5. 必须满足的不变量

1. **保序保形**：不改变行数、行顺序，不增删任何非敏感字符。
2. **不重叠**：同一段文本只被一条规则处理一次，不做二次替换。
3. **幂等**：`desensitize(desensitize(x)) == desensitize(x)` 对任意输入成立。
4. **纯标准库**：只使用 Python 标准库。
5. **不修改**隐藏测试、提交契约或平台目录。

## 6. 答疑记录

以下问题在出题评审时已被提出并有明确结论。它们不是提示，是**规格的一部分**，请在你的 `SPEC.md` 中体现相应决策。

**Q1：一串 18 位数字，既满足身份证长度也落在银行卡的 16–19 位区间，按哪条处理？**
先判身份证。只有第 7–14 位构成合法出生日期时才算身份证；否则按银行卡处理。例如 `622202123456789012` 的第 7–14 位是 `12345678`，`1234` 不是 `19xx`/`20xx`，因此它是银行卡。

**Q2：密钥的值本身是邮箱或 IP，按哪条处理？**
密钥规则优先，值整体替换为 `***`，不再对值内部做识别。`token=user@mail.com` → `token=***#<标记>`，标记取自 `user@mail.com`。

**Q3：密钥的值被引号包裹怎么办？**
引号原样保留，只脱敏引号内的值：`password="p@ss"` → `password="***#<标记>"`。值以空白、逗号、分号或引号为终止。

**Q4：为什么幂等能成立？**
掩码字符 `*` 不属于任何规则的合法值字符集。已脱敏文本再次处理时，所有规则都无法在掩码位置重新匹配。实现时请确保这一点，不要依赖「检测是否已脱敏」这种脆弱做法。

**Q5：`999.888.777.666` 这种点分十进制要脱敏吗？**
不要。任一段超过 255 就不是 IPv4，原样保留。

**Q6：12 位纯数字（如 `138001380001`）会被当成手机号吗？**
不会。手机号必须恰好 11 位，前后不能紧邻其他数字。所有数字类规则都要做数字边界检查。

**Q7：邮箱本地部分只有 1 个字符怎么办？**
仍然保留首字符再接 `***`：`a@x.com` → `a***@x.com`。`***` 是固定三个星号，不随本地部分长度变化。

**Q8：非法输入怎么处理？**
`text` 不是字符串，或 `level` 不是受支持的取值，抛出你自己定义的异常（继承 `ValueError`）。空字符串是合法输入，原样返回。

## 8. SDD 交付要求

三份交付件都参与评分，缺一份直接判为不完整交付。

### 8.1 `SPEC.md`

必须包含以下七个一级或二级标题（标题文字需包含括号内关键词）：

1. `## 1. 目标与范围`（范围）

3. `## 3. 脱敏规则规格`（规则）
4. `## 4. 验收用例`（验收）— 表格形式，每行必须有具体输入和期望输出
5. `## 5. 异常与边界`（边界）
6. `## 6. 变更影响分析`（变更）
7. `## 7. 验证结论`（验证）

`## 4. 验收用例` 至少 8 条，其中至少 3 条属于异常或边界。用例必须是**可执行的**：给出确切输入字符串和确切期望输出字符串，不能只写「应正确处理手机号」。

### 8.2 `transcript.md`

与 AI 协作的过程记录，必须按轮次组织。每一轮使用固定格式：

```markdown
## Round 2 · SPEC

**Prompt**

> 你贴给 AI 的提示词原文

**Response**

AI 回应的要点摘要（不需要全文）

**Verification**

你如何验证这一轮的产出，结论是什么
```

`Round N · PHASE` 中的 `PHASE` 必须取自：`CLARIFY` `SPEC` `ACCEPTANCE` `IMPLEMENT` `VERIFY` `CHANGE` `REGRESSION`。

至少 5 轮，且必须包含 `SPEC`、`IMPLEMENT`、`VERIFY` 三个阶段；完成变更包后还需包含 `CHANGE` 和 `REGRESSION`。

**顺序会被检查**：第一个 `IMPLEMENT` 轮次必须出现在第一个 `SPEC` 轮次之后。先让 AI 写代码、再补规格，属于非 SDD 流程，`P1` 会被判 D。
