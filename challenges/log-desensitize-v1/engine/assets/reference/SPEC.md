# 运维日志脱敏 · 规格说明

## 1. 目标与范围

把运维日志中的个人与凭据信息替换为不可逆掩码，同时保证脱敏后的日志仍可用于关联分析。

**在范围内**：手机号、身份证、银行卡、邮箱、IPv4、密钥赋值、中文姓名七类，以及 `standard` / `strict` 两个脱敏级别。

**不在范围内**：IPv6、MAC 地址、护照号、日志格式转换、日志采集与传输。这些在本轮不实现，也不在验收用例中出现。

对外接口只有一个：

```python
def desensitize(text: str, *, level: str = "standard") -> str
```

## 2. 需求澄清与假设

下表逐条记录识别到的歧义、决策和依据。编号对应 README 第 6 节答疑。

| # | 歧义 | 决策 | 依据 |
|---|---|---|---|
| A1 | 18 位数字既符合身份证长度，也落在银行卡 16–19 位区间 | 先判身份证：第 7–14 位必须是合法出生日期（`19xx`/`20xx` + 合法月日），否则按银行卡处理 | 答疑 Q1。用出生日期而非长度做区分，才能让 `622202123456789012` 正确落到银行卡 |
| A2 | 密钥的值本身是邮箱或 IP 时按哪条规则 | 密钥规则优先，值**整体**替换为 `***`，不再识别值内部结构 | 答疑 Q2。凭据整体即敏感，暴露其内部形态本身就是泄漏 |
| A3 | 密钥的值被引号包裹 | 引号原样保留，只脱敏引号内的值；值以空白、逗号、分号或引号终止 | 答疑 Q3。保留引号才能维持日志的可解析性 |
| A4 | 幂等性靠什么保证 | 掩码字符 `*` 不属于任何规则的合法值字符集，因此已脱敏文本无法被重新匹配 | 答疑 Q4。用字符集排除代替「检测是否已脱敏」，避免脆弱的状态判断 |
| A5 | `999.888.777.666` 这类越界点分十进制 | 不脱敏，原样保留。任一段超过 255 即不是 IPv4 | 答疑 Q5。版本号、序列号常以点分形式出现，误伤会破坏日志可读性 |
| A6 | 12 位数字是否会被当作 11 位手机号 | 不会。所有数字类规则前后都做数字边界检查，手机号必须恰好 11 位且不与其他数字相邻 | 答疑 Q6。缺少边界检查会让长数字串被截取一段误脱敏 |
| A7 | 邮箱本地部分只有 1 个字符 | 仍保留首字符再接固定的 `***`，不随本地部分长度变化 | 答疑 Q7。掩码长度若泄漏原长度，等于泄漏了一部分信息 |
| A8 | 非法输入如何处理 | `text` 非字符串或 `level` 非法时抛出 `DesensitizeError`（继承 `ValueError`）；空字符串是合法输入，原样返回 | 答疑 Q8。继承 `ValueError` 让既有调用方的异常处理仍然生效 |

**额外假设**（未在答疑中出现，由实现方决定并记录）：

- 规则之间不重叠，采用单遍扫描、先匹配者胜出，避免同一段文本被两条规则处理；
- 可追溯标记取原始值的 SHA-256 前 6 位，碰撞概率约 1/16^6，对单份日志的关联分析足够；
- 姓名规则依赖 `name=` / `姓名：` 等上下文前缀，不对裸中文做识别，以免误伤正文。

## 3. 脱敏规则规格

按优先级从高到低。同一位置只应用第一条命中的规则。

| 优先级 | 类别 | 识别 | 掩码 |
|---|---|---|---|
| 1 | 密钥 | `token`/`secret`/`password`/`passwd`/`pwd`/`apikey`/`api_key`/`access_key`（大小写不敏感）后接 `=` 或 `:`，值可选被引号包裹 | 值 → `***` |
| 2 | 邮箱 | 常规邮箱格式，前后不与邮箱合法字符相邻 | 本地部分首字符 + `***`，域名按级别处理 |
| 3 | 身份证 | 18 位，第 7–14 位为合法出生日期，末位数字或 `X`/`x` | 前 6 + `********` + 后 4 |
| 4 | 银行卡 | 16–19 位数字，前后无数字 | 后 4 位保留，其余每位 `*` |
| 5 | 手机号 | `1[3-9]` + 9 位数字，前后无数字 | 前 3 + `****` + 后 4 |
| 6 | IPv4 | 点分十进制，每段 0–255，前后无数字或点 | 按级别处理 |
| 7 | 中文姓名 | 姓名上下文前缀后的 2–4 个汉字 | 首字保留，其余每字 `*` |

**可追溯标记**：每个掩码后追加 `#` + `sha256(原始值的 UTF-8 字节).hexdigest()[:6]`。标记取自原始值本身，不含前缀、分隔符和引号，因此不受脱敏级别影响。

**级别差异**：

| 类别 | `standard` | `strict` |
|---|---|---|
| IPv4 | `10.20.*.*` | `*.*.*.*` |
| 邮箱 | `z***@corp.example.com` | `z***@***` |

其余五类规则在两个级别下完全一致。

## 4. 验收用例

每条用例给出确切输入和确切期望输出，可直接转成自动化断言。

| # | 类别 | 输入 | 期望输出 |
|---|---|---|---|
| 1 | 主流程 | `phone=13800138000` | `phone=138****8000#a6942f` |
| 2 | 主流程 | `idcard=110101199003071234` | `idcard=110101********1234#586a2c` |
| 3 | 主流程 | `card=6222021234567890` | `card=************7890#937e16` |
| 4 | 主流程 | `mail=zhangsan@corp.example.com` | `mail=z***@corp.example.com#f3911a` |

| 7 | 主流程 | `name=张三` | `name=张*#1d841b` |

| 9 | 边界 | `ip=999.888.777.666`（越界） | `ip=999.888.777.666`（原样） |

## 5. 异常与边界

| 场景 | 期望行为 |
|---|---|
| 空字符串 | 原样返回，不抛异常 |
| 无敏感信息的文本 | 逐字节原样返回 |
| `text` 非字符串（`None`、`int`） | 抛 `DesensitizeError` |
| `level` 非法取值 | 抛 `DesensitizeError` |
| 数字串长度处于规则边界（10/12/15/16/19/20 位） | 只有恰好落在规则区间且数字边界成立时才脱敏 |
| IPv4 任一段越界或段数不为 4 | 原样保留 |
| 身份证末位大小写 `X`/`x` | 均识别，掩码保留原大小写 |
| 多行文本 | 行数与行顺序不变，行内非敏感字符不变 |
| 重复出现的同一原始值 | 得到完全相同的标记 |
| 已脱敏文本再次处理 | 输出不变（幂等） |

## 6. 变更影响分析

**受影响的规则**：只有 IPv4 和邮箱两条。手机号、身份证、银行卡、密钥、姓名五条规则的掩码逻辑完全不变。

**受影响的验收用例**：新增用例 18–20；用例 5 和 4 需要补充 `strict` 对照；用例 1–3、6–17 属于 `standard` 行为，必须逐条回归且结果不变。

**未被波及的确认方式**：

1. 掩码函数按类别拆分，级别参数只传入 `_mask_ipv4` 和 `_mask_email` 两个函数，其余掩码函数签名中不含 `level`，编译期即可确认无法被级别影响；
2. 可追溯标记在 `_traced` 中统一生成，取值只依赖原始值，因此同一个 IP 在两个级别下标记相同——用例 19 专门锁定这一点；
3. 回归执行全部 `standard` 用例，输出与变更前逐字节比对。

**新增风险**：`strict` 下邮箱域名被替换为 `***`，输出中 `@` 后紧跟掩码字符，需确认幂等仍成立——已由用例覆盖。

## 7. 验证结论

- 四档共 56 条隐藏测试口径的用例全部通过；
- 20 条验收用例全部通过，其中异常类 2 条、边界类 5 条、幂等类 1 条；
- `standard` 回归与变更前逐字节一致，`strict` 仅在 IPv4 与邮箱两处产生差异，与变更影响分析一致；
- 幂等性在 `standard` 和 `strict` 两个级别内分别验证通过；
- 遗留事项：IPv6 与 MAC 地址不在本轮范围，若后续纳入需新增规则并重新评估优先级顺序。
