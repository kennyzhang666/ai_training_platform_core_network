# 运维日志脱敏工具 SPEC

## 1. 目标与非目标

目标是为内网运维日志提供确定、可复现、可审计的单行脱敏组件：对 JSON 日志和普通文本日志识别手机号、身份证、邮箱、IPv4 地址和令牌，将其替换为保留最小排障语义的掩码。相同输入、规则版本和工具版本必须产生相同输出。工具同时服务运维排障、隐私保护和审计复核，任何一类诉求都不能依赖保存完整敏感原文。

非目标包括：不做身份真实性校验，不连接外部 DLP 服务，不负责日志采集、传输、索引或长期存储，不承诺识别题面之外的全部敏感数据。新增类型必须通过规则版本进入，不能临时加入未审查表达式。

## 2. 范围与约束

输入是一行 UTF-8 文本，可以是合法 JSON、普通文本或畸形 JSON；输出始终是一行 UTF-8 文本。实现只使用 Python 3.11 标准库，不访问网络，不读取运行主机凭据。默认最大行长为 1 MiB，调用方在进入组件前执行限制；组件资源上限为单行处理 100 ms、内存增量 8 MiB。多行异常堆栈逐行处理，不在组件内拼接，避免无界缓冲。

REQ-01：支持普通文本中的五类敏感数据脱敏。
REQ-02：递归处理 JSON 对象和数组中的字符串值，并保持数值、布尔、空值类型。
REQ-03：对 Unicode 文本保真，输出不得把中文转换为不可读转义序列。
REQ-04：畸形 JSON 安全降级为普通文本规则，不得原样旁路。
REQ-05：脱敏必须幂等，第二次处理不得恢复信息或继续破坏掩码。
REQ-06：无效规则、错误参数和资源超限必须显式失败，不得静默输出原文。

## 3. 关键假设与决策记录

### 3.1 歧义清单

歧义一：IP 是否全部脱敏。假设私网和公网 IPv4 都属于敏感运维定位信息，决策为保留前两段、隐藏后两段。歧义二：畸形 JSON 是否直接报错。假设其仍可能是普通日志，决策为进入普通文本规则；只有调用参数或规则本身无效时失败关闭。歧义三：邮箱是否保留域名。假设域名对业务归属排查有价值，决策为保留首字符和完整域名。

### 3.2 关键假设

- 每次调用只处理一行，不跨行组合身份证或令牌。
- 日志使用 UTF-8；编码转换由上游完成。
- 规则只处理字符串值，数字和布尔值不转换。
- 运维、隐私和审计负责人接受最小必要可读性原则。

### 3.3 决策记录

DEC-01：合法 JSON 先解析再递归处理，以保持结构和类型。
DEC-02：普通文本使用固定顺序的预编译正则。
DEC-03：规则由 `DEFAULT_RULES` 命名集合提供，并允许注入冻结规则集合。
DEC-04：诊断只允许稳定错误码、规则版本、计数和脱敏后摘要；不得记录原文。

## 4. 敏感数据分类与规则表

规则表按固定规则优先级执行。若新增表达式产生冲突，优先选择更具体、泄露风险更高的规则，并升级规则版本。禁止依赖字典遍历的偶然顺序。

| 标识 | 敏感类型 | 输入示例 | 期望输出 | 保留依据 |
| --- | --- | --- | --- | --- |
| MOBILE | 手机号 | `13812348000` | `138****8000` | 保留号段和尾号用于排障 |
| IDENTITY | 身份证 | `110101199001011234` | `110101********1234` | 保留地区与尾段 |
| EMAIL | 邮箱 | `alice@example.com` | `a***@example.com` | 保留域名 |
| IP | IPv4 | `10.20.30.40` | `10.20.*.*` | 保留网络段 |
| TOKEN | 令牌 | `token=secret` | `token=***` | 不保留凭据内容 |

掩码本身不得再次命中为完整敏感值。每条规则必须覆盖命中、未命中、已脱敏输入和与其他规则冲突四类用例。

## 5. 输入输出与接口契约

公开接口为 `redact_line(line: str, rules: Sequence[Rule] | None = None) -> str`。`line` 非字符串时抛出 `TypeError`；规则集合包含非 `Rule` 值时抛出 `ValueError`。`rules=None` 使用冻结的 `DEFAULT_RULES`。

合法 JSON 输入经过 `json.loads`、递归脱敏和 `json.dumps(ensure_ascii=False, sort_keys=True)` 输出。对象键不参与脱敏，字符串值递归处理，空值 `null`、数值、布尔值保持原类型。普通文本保持非敏感字符顺序，只替换命中片段。输入末尾换行由命令入口处理，库函数不返回换行。

命令接口为 `python src/log_redactor.py --input <path> --output <path>`。读取、写入和权限错误以非零退出码结束，不创建伪造成功结果。

## 6. 处理流程与组件设计

组件分为四个职责：`redact_text` 按规则顺序处理字符串；`redact_record` 递归处理 Mapping 和 Sequence；`redact_line` 判断 JSON 或普通文本路径；`main` 负责流式文件读写。解析、匹配、结构遍历和 I/O 不共享可变状态。

主流程为：校验输入类型 → 尝试 JSON 解析 → 成功则递归处理所有字符串值 → 失败则按普通文本处理 → 使用稳定格式输出。每次调用读取同一不可变规则集合，不缓存原始输入。嵌套对象和数组会创建脱敏后的新结构。

## 7. 异常、边界与失败策略

失败策略遵循失败关闭：参数或规则无效时立即抛出稳定异常，不返回原文；畸形 JSON 进入普通文本脱敏，仍应用全部文本规则。最大行长和资源上限由上游强制，超限输入返回 `LINE_TOO_LARGE`，不截断后继续处理，避免敏感值被截断成无法识别的片段。

边界包括空字符串、空值字段、空对象、深层嵌套、Unicode 姓名和域名、超长字段、多行堆栈逐行处理、同一行多次命中、已经脱敏的值、规则冲突和畸形 JSON。诊断只记录总处理数、命中规则计数、规则版本、耗时分桶和稳定错误码；样本只允许脱敏后摘要，任何情况下不得记录原文。

## 8. 验收标准与用例

AC-01：输入普通文本 `mobile=13812348000 token=secret`，期望输出 `mobile=138****8000 token=***`，判定为完整敏感值不存在。
AC-02：输入合法 JSON，期望输出保持 JSON 类型，手机号被脱敏，`status=200` 与 `ok=true` 保持原类型。
AC-03：输入嵌套对象与数组，期望所有字符串叶子递归脱敏，结构不变。
AC-04：输入 Unicode 中文与邮箱，期望输出可读中文并脱敏邮箱。
AC-05：输入畸形 JSON，期望按普通文本脱敏，不因解析失败旁路。
AC-06：输入无效规则对象，期望抛出 `ValueError`，判定为未返回原始日志。

每个验收用例记录输入、期望输出和判定。主流程由 `test_plain_text` 与 `test_json` 验证；异常路径由 `test_malformed` 与 `test_invalid_rules` 验证；嵌套、Unicode、幂等和规则变化由对应测试验证。

## 10. 可观测性与安全

允许指标包括处理成功数、失败数、规则命中计数、输入长度分桶、时延和规则版本。禁止记录输入行、完整匹配值、异常对象中的原始上下文、访问令牌、Cookie 和文件正文。错误响应使用 `INVALID_INPUT`、`INVALID_RULE`、`LINE_TOO_LARGE` 和 `IO_FAILURE` 等稳定代码。审计只保存工具版本、规则版本、调用方和结果状态。

安全复核检查正则灾难性回溯、规则绕过、日志注入、Unicode 保真和错误路径原文泄露。发布前只使用脱敏后的合成样本，不使用真实员工或客户日志。

## 11. 变更与回滚

规则版本采用语义化版本；新增敏感类型升次版本，改变已有掩码语义升主版本。向后兼容定义为同一主版本内已有五类规则的掩码形状和接口异常保持不变。变更影响分析覆盖解析、规则匹配、递归处理、输出格式、指标、文档和测试组件，并标记影响范围。

回归清单包括普通文本、JSON、嵌套、Unicode、畸形输入、幂等、无效规则、自定义规则和规则冲突，发布前执行全量测试。当前已确定出现误脱敏时应恢复到稳定规则包，但具体操作顺序、恢复后的校验入口和负责人仍需在上线前确认。
