# AI 协作记录

## 协作原则

本次采用“先写规格，再实现”的顺序。首次任务先提供角色、运维日志治理上下文、隐私约束、输出格式和验收标准，要求 AI 不直接生成代码；关键假设由人工确认后写入 `SPEC.md` 和追踪矩阵，再实现最小闭环。

## 可复用提示词

角色：你是负责内网日志治理的资深 Python 工程师。上下文：输入包含 JSON 与普通文本运维日志。约束：只用 Python 3.11 标准库；不得泄露原文；输出必须确定、幂等；遇到不确定规则先列假设。输出格式：先给需求编号、规则表、接口和验收标准，再给实现计划。检查清单：逐项核对边界用例、规则冲突、失败关闭、Unicode、追踪矩阵和回滚，不得泄露任何完整敏感值。

## 关键假设与确认

- 假设单次输入是一行 UTF-8 文本；已与出题要求确认。
- 假设畸形 JSON 降级为普通文本处理；已确认该行为仍必须应用全部脱敏规则。
- 假设非字符串 JSON 字段保持原类型；已确认数值和布尔值不得转成字符串。
- 核验对象：手机号、身份证、邮箱、IP 和令牌。证据来自题面要求和 SPEC 规则表，结论为五类规则均进入首版。

## 迭代 1：规格与追踪

本轮目标：完成需求澄清、关键假设、决策记录、规则表与验收标准。验证命令：人工逐项检查 REQ、AC 与测试名称是否双向对应。验证结果：追踪矩阵覆盖 6 条验收标准。先写规格，再实现；失败点是第一版没有说明畸形 JSON，调整后增加失败关闭和普通文本降级决策。

## 迭代 2：最小实现

本轮目标：完成普通文本和 JSON 主流程。验证命令：`python -m unittest discover -s tests -p "test_*.py" -v`。验证结果：主流程测试通过；静态检查确认源码可解析。失败点是 JSON 默认转义中文，调整为 `ensure_ascii=False` 并增加 Unicode 测试。

## 迭代 3：边界与安全

本轮目标：覆盖嵌套结构、畸形输入、幂等和无效规则。验证命令：单元测试后逐项搜索原始日志输出。验证结果：9 项测试通过，未发现 `print(line)` 或原文落盘。失败点是初版二次脱敏会继续修改部分占位符，调整规则后幂等测试通过。

## 变更请求与影响分析

变更请求：增加自定义主机名规则，并保持现有规则优先级。影响文件：`src/log_redactor.py` 的规则注入入口、`SPEC.md` 规则版本和 `README.md` 扩展说明。影响测试：`test_custom_rule`、`test_rule_change` 和全量 9 项测试。

变更回归：执行完整 unittest 与静态检查，复测通过。回滚依据：规则集合按版本冻结；出现误脱敏时切回上一规则版本，重新执行主流程、边界和幂等测试后恢复处理。
