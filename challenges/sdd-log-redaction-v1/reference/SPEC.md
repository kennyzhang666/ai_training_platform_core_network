# 运维日志脱敏工具 SPEC

## 1. 目标与非目标

目标是为内网运维日志提供一个确定、可复现、可审计的单行脱敏组件：对 JSON 日志和普通文本日志识别手机号、身份证、邮箱、IPv4 地址和令牌，将其替换为保留最小排障语义的掩码；相同输入、规则版本和工具版本必须产生相同输出。工具服务运维排障、隐私保护和审计复核三类诉求，任何一类诉求都不能通过记录完整敏感原文实现。

非目标包括：不做用户身份真实性校验，不尝试自然语言实体识别，不连接外部 DLP 服务，不负责日志采集、传输、索引或长期存储，不承诺识别题面之外的全部敏感数据。无法可靠识别的新增类型必须通过规则版本升级进入，不能临时写入未审查表达式。

## 2. 范围与约束

输入范围是一行 UTF-8 文本，既可能是合法 JSON 值，也可能是普通文本或畸形 JSON。输出始终是一行 UTF-8 文本。实现只使用 Python 3.11 标准库，不访问网络，不读取运行主机凭据，不在输入目录之外写临时文件。默认最大行长为 1 MiB；上层调用方应在进入组件前执行限制，本组件的资源上限为单行处理 100 ms、内存增量 8 MiB。多行异常堆栈由调用方逐行处理，不在组件内部拼接，以避免无界缓冲。

REQ-01：必须支持普通文本中的五类敏感数据脱敏。
REQ-02：必须递归处理 JSON 对象和数组中的字符串值，并保持数值、布尔、空值类型。
REQ-03：必须对 Unicode 文本保真，输出不得把中文转换为不可读转义序列。
REQ-04：畸形 JSON 必须安全降级为普通文本规则，不得原样旁路。
REQ-05：脱敏必须幂等，第二次处理不得恢复信息或继续破坏掩码。
REQ-06：无效规则、错误参数和资源超限必须显式失败，不得静默输出原文。

## 3. 关键假设与决策记录

### 3.1 歧义清单

歧义一：IP 是否全部脱敏。假设私网和公网 IPv4 均属于敏感运维定位信息，决策为保留前两段、隐藏后两段。歧义二：畸形 JSON 是否报错。假设其仍可能是有效普通日志，决策为进入普通文本规则；只有调用参数或规则本身无效时失败关闭。歧义三：邮箱是否保留域名。假设域名对业务归属排查有价值，决策为仅保留首字符与完整域名。

### 3.2 关键假设

- 每次调用只处理一行，不跨行组合身份证或令牌。
- 日志使用 UTF-8；编码转换由上游完成。
- 规则匹配只针对字符串值，数字和布尔值不转换。
- 运维、隐私和审计负责人接受“最小必要可读性”原则。

### 3.3 决策记录

DEC-01：合法 JSON 先解析再递归处理，以保持结构和类型。
DEC-02：普通文本使用固定顺序的预编译正则。
DEC-03：所有规则由 `DEFAULT_RULES` 命名集合提供，并允许调用方注入冻结规则集合。
DEC-04：诊断只允许稳定错误码、规则版本、计数和脱敏后摘要；不得记录原文。

## 4. 敏感数据分类与规则表

规则表按固定规则优先级执行：TOKEN → IDENTITY → MOBILE → EMAIL → IP 的业务概念优先级在发布前冻结；当前 `DEFAULT_RULES` 的实际顺序经过无重叠验证。若新增表达式产生冲突，优先选择更具体、泄露风险更高的规则，并在规则版本中升版。禁止依赖字典遍历偶然顺序。

| 标识 | 敏感类型 | 输入示例 | 期望输出 | 保留依据 |
| --- | --- | --- | --- | --- |
| MOBILE | 手机号 | `13812348000` | `138****8000` | 保留号段和尾号用于排障 |
| IDENTITY | 身份证 | `110101199001011234` | `110101********1234` | 保留地区与校验尾段 |
| EMAIL | 邮箱 | `alice@example.com` | `a***@example.com` | 保留域名用于归属判断 |
| IP | IPv4 | `10.20.30.40` | `10.20.*.*` | 保留网络段 |
| TOKEN | 令牌 | `token=secret` | `token=***` | 不保留任何凭据内容 |

掩码本身不得再次命中为完整敏感值。每条规则必须给出命中、未命中、已脱敏输入和与其他规则冲突四类用例。

## 5. 输入输出与接口契约

公开接口为 `redact_line(line: str, rules: Sequence[Rule] | None = None) -> str`。`line` 非字符串时抛出 `TypeError`；规则集合包含非 `Rule` 值时抛出 `ValueError`。`rules=None` 使用冻结的 `DEFAULT_RULES`；传入空集合表示调用方明确要求不应用规则，但生产配置不得使用空集合。

合法 JSON 输入经过 `json.loads`、递归脱敏和 `json.dumps(ensure_ascii=False, sort_keys=True)` 输出。对象键不参与脱敏，字符串值递归处理，空值 `null`、数值、布尔值保持原类型。普通文本保持非敏感字符顺序，只替换命中片段。输入末尾换行由命令入口统一处理，库函数不返回换行。

命令接口为 `python src/log_redactor.py --input <path> --output <path>`。读取失败、写入失败和权限错误直接以非零退出码结束；不得创建带“成功”标记的空输出。

## 6. 处理流程与组件设计

组件包括四个职责：`redact_text` 按规则顺序处理字符串；`redact_record` 递归处理 Mapping 和 Sequence；`redact_line` 判断 JSON 或普通文本路径；`main` 负责文件流式读写。解析、匹配、结构遍历和 I/O 互不共享可变全局状态。

主流程如下：校验输入类型 → 尝试 JSON 解析 → 成功则递归处理所有字符串值 → 失败则按普通文本处理 → 使用稳定格式输出。每次调用读取同一不可变规则集合，不缓存原始输入。对于嵌套对象和数组，递归只创建脱敏后的新结构，不修改调用方对象。

## 7. 异常、边界与失败策略

失败策略遵循失败关闭：如果参数或规则无效，立即抛出稳定异常，不返回原文；如果只是畸形 JSON，则进入普通文本脱敏，因为仍可安全应用全部文本规则。最大行长和资源上限由上游在调用前强制，超限输入返回 `LINE_TOO_LARGE`，不截断后继续处理，避免敏感值被截断成无法识别的片段。

边界包括空字符串、空值字段、空对象、深层嵌套、Unicode 姓名和域名、超长字段、多行堆栈的逐行处理、同一行多次命中、已经脱敏的值、规则冲突和畸形 JSON。对于诊断与可观测性，只记录总处理数、命中规则计数、规则版本、耗时分桶和稳定错误码；样本仅允许脱敏后摘要，任何情况下不得记录原文。

## 8. 验收标准与用例

AC-01：输入普通文本 `mobile=13812348000 token=secret`，期望输出为 `mobile=138****8000 token=***`，判定为完整敏感值不存在。
AC-02：输入合法 JSON，期望输出保持 JSON 类型，手机号被脱敏，`status=200` 与 `ok=true` 保持原类型。
AC-03：输入嵌套对象与数组，期望所有字符串叶子递归脱敏，结构不变。
AC-04：输入 Unicode 中文与邮箱，期望输出可读中文并脱敏邮箱。
AC-05：输入畸形 JSON，期望输出按普通文本脱敏，不因解析失败旁路。
AC-06：输入无效规则对象，期望抛出 `ValueError`，判定为未返回任何原始日志。

验收用例必须同时记录输入、期望输出和判定。主流程由 `test_plain_text` 与 `test_json` 验证；异常路径由 `test_malformed` 与 `test_invalid_rules` 验证；嵌套、Unicode、幂等和规则变化分别由对应测试验证。

## 10. 可观测性与安全

允许指标：处理成功数、失败数、各规则命中计数、输入长度分桶、处理时延、规则版本。禁止内容：输入行、完整匹配值、异常对象中的原始上下文、访问令牌、Cookie 和文件正文。错误响应使用 `INVALID_INPUT`、`INVALID_RULE`、`LINE_TOO_LARGE`、`IO_FAILURE` 等稳定代码。审计记录只保存工具版本、规则版本、调用方标识和结果状态。

安全复核检查正则灾难性回溯、规则绕过、日志注入、Unicode 保真和错误路径原文泄露。发布前使用脱敏后的合成样本，不使用真实员工或客户日志。

## 11. 变更与回滚

规则版本使用语义化版本，新增敏感类型升次版本，改变已有掩码语义升主版本。向后兼容定义为：同一主版本内已有五类规则的掩码形状和接口异常保持不变。变更影响分析必须覆盖解析、规则匹配、递归处理、输出格式、指标、文档和测试组件，并标注影响范围。

回归清单包括普通文本、JSON、嵌套、Unicode、畸形输入、幂等、无效规则、自定义规则和规则冲突，发布前执行全量测试。回滚步骤：停止新规则版本调用 → 切换到上一规则版本 → 用冻结样本执行全量测试 → 比较输出摘要 → 恢复流量。回滚验证要求主流程与安全失败路径全部通过，并确认指标不包含原文。
