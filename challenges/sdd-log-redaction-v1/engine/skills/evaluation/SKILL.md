# SDD 日志脱敏规格评测

## 目标

对冻结的日志脱敏交付件进行可复现、可审计的综合评测。评分事实由评测引擎产生；本 Skill 规定证据读取、交叉核验和结果检查方式。

## 必须读取

- `SPEC.md`：主要评分证据。
- `README.md`：运行与复现入口。
- `AI_WORKLOG.md`：需求澄清、提示词结构、验证和迭代证据。
- `src/log_redactor.py`：实现与规格一致性。
- `tests/test_log_redactor.py`：验收与边界测试映射。

## 核验方法

1. 先建立需求编号、设计决策、验收标准和测试名称的追踪关系。
2. 再检查结构化与非结构化日志、嵌套字段、Unicode、畸形输入、规则冲突和失败关闭策略。
3. 运行评测入口，不依据文件长度或关键词单独给出语义结论；自动检查结果必须与可定位原文共同作为证据。
4. 规格与实现冲突时，以实际交付事实记录差异，不替学员推断未写出的设计。
5. 每个低于 A 档的评分点至少产生一条具体修改建议；建议应指向交付件中的文件与位置。

## 结果检查

- 16 个评分点不得缺项或重复。
- 每个维度分数等于该维度评分点之和，总分等于四个维度之和。
- 证据不得包含其他学员内容、令牌、Cookie、密钥或未脱敏原始日志。
- 单份失败只进入该运行的失败记录，不得阻断批次中的其他提交。
