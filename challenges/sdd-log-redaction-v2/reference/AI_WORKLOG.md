# AI 协作记录

## 初始任务与规格先行

角色设定为“生产日志治理工程师与规格审查员”。上下文包含运维日志会进入隐私与审计流程，输入不可信，运行环境可信。首次提示给出目标、威胁边界、约束和验收标准，明确先写规格、再实现，禁止直接生成可运行代码。

关键假设是关联字段需要跨行稳定但不得可逆。AI 首次建议普通 SHA-256；人工核验低熵工号可被字典反推后未确认该方案，改为 HMAC-SHA256，并确认密钥由 `LOG_REDACTION_KEY` 注入。结论同步回 `SPEC.md`、策略契约和需求追踪矩阵。

## 迭代 1：需求与威胁建模

本轮目标：完成目标、非目标、数据分类、歧义、失败关闭与 AC-01～AC-12。验证命令：人工逐项核对 SPEC.md 标题和追踪关系。验证结果：发现畸形 JSON 降级为普通文本无法证明安全，调整为固定 `MALFORMED_JSON` 标记。

失败：最初把所有标识都替换为 `***`，丢失跨记录排障能力。原因：未区分“凭据字段”和“关联字段”。调整：增加 `secretFields` 与 `correlationFields` 两类策略，并为关联字段采用 HMAC。

## 迭代 2：核心实现

本轮目标：实现策略校验、文本规则、递归 JSON 与 HMAC 别名。验证命令：`python -m unittest discover -s tests -p "test_*.py" -v`。验证结果：基础文本、嵌套结构、类型保真和关联用例通过。

失败：手机号规则先执行时会截取身份证号码片段。原因：规则优先级未冻结。调整：建立 `RULE_PRIORITY`，把身份证号放在手机号之前，并增加 `test_rule_priority`。

## 迭代 3：安全边界

本轮目标：实现缺密钥、畸形 JSON、超长行、无效策略和诊断无原文。验证命令：运行四个安全失败公开测试，再执行 `python -m compileall -q src tests`。验证结果：稳定错误码正确，标准错误不包含待处理值。

失败：命令行捕获异常时直接打印异常对象可能暴露文件上下文。原因：错误模型没有限制输出格式。调整：只输出 `ERROR <稳定错误码>`，提示词检查清单新增“不得泄露原文与异常堆栈”。

## 迭代 4：流式与批量验证

本轮目标：证明实现不调用 `read()` 或 `readlines()`，统计与输出行数一致，并完成批量强度验证。验证命令：运行 `test_streaming`、2000 行单次迭代器检查、全量 unittest 与 compileall。验证结果：逐行处理、批量计数和处理时限均通过。

公开测试不能知道平台隐藏输入，因此提示词要求面向契约实现，不针对样例硬编码；提交前逐项核对核心、复杂、安全、工程四类隐藏用例所代表的能力边界。
