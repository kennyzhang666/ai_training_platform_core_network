# SDD 日志脱敏进阶评测

## 目标

对冻结交付件执行确定、可复现、无原文泄露的综合评测。隐藏用例是功能与安全事实，规格原文用于判断设计完整性和追踪关系，二者不得相互替代。

## 必读证据

- `SPEC.md`：需求、威胁边界、优先级、错误语义、验收和回滚。
- `policy/redaction_policy.json`：版本、资源边界、密钥入口和字段分类。
- `src/log_redactor.py`：单行、递归、HMAC、流式和 CLI 实现。
- `tests/test_log_redactor.py`：公开验收与回归入口。
- `AI_WORKLOG.md`：规格先行、核验、迭代、变更和复测事实。

## 核验方法

1. 先运行学员测试，再运行四层隐藏用例；禁止从文件长度或关键词推断功能通过。
2. 核对同一需求在规格、策略、实现和测试中的稳定编号与行为是否一致。
3. 检查隐藏失败是否集中在规则冲突、HMAC、失败关闭或真流式边界，并把建议定位到学员文件。
4. 结果只保留用例编号与计数；任何异常文本都必须确认不含测试密钥或原始敏感值。
5. 16 个评分点不得缺项或重复，四维小计和总分必须可由评分点重算。

## 失败处理

- 评测进程异常时记录稳定诊断码，不复制标准错误中的学员日志。
- 单项隐藏用例失败按对应判据降档；不得将整个交付件直接记零。
- 每个低于 A 档的评分点至少提供一条明确、可执行且不泄露隐藏答案的建议。
